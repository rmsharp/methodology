Terms used below, as the maintainer and the PR use them. The *trimmer* moves the oldest records of a growing ledger file into an archive file, a *shard*, and writes a *proof* beside it: a script (`<shard>.verify.sh`) that re-checks from git that the move lost nothing. The commit that adds the shard is the *trim commit*. *Record 0* is the newest record of the ledger. A *stub* is the placeholder record a session commits when it claims its work; the *finalize* overwrites it with the finished record. `--reverify <shard>` builds a fresh proof from the running trimmer's template and runs it. A proof's exit code: 0 holds, 1 a failure, 3 "did not finish, no verdict", 4 a recognised stub finalize (still a failure).

## 2. A finding that is not on the maintainer's list

The proof finds the trim commit with `git log --diff-filter=A` and ignored that command's failure. If the walk fails (a treeless partial clone whose remote is gone, a damaged object store), the proof behaves as if the trim were not yet committed, compares the live ledger with itself, and prints `OK: L1, L2/front-matter, L3 hold` having compared nothing. Present in 1.5.0, 1.8.1 and every version between. A failed walk is now exit 3. It is its own commit (`1670c5d`, 2 mutants killed) and can be dropped without touching the nine; the reply says so. Of everything found it is the most serious in kind: a pass that compared nothing, where the others were a wrong exit code or a missing label.

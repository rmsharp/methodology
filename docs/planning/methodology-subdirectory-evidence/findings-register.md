# BL-101 findings register — what the adopter runs taught, and what became of it

Plan [`methodology-subdirectory-plan.md`](../methodology-subdirectory-plan.md) §7.6 (the operator's addition, 2026-10-09: *"The plan must include learning from experience to be useful."*). **Why it exists:** an adopter that later syncs from `upstream` has no agent rehearsing in clones and matching refused files by hand, so each run must leave that route safer, and a finding left in a record's prose does not.

**How to use it.** Read it before an adopter session. Add a row for every finding of the run; the disposition is **fixed** (the change and the test that holds it), **open** (where it is tracked) or **declined** (why). *Seen* asks whether the tool's own checks reported it: a **no** is the kind §7.6 puts first. Rows are not rewritten; a change of disposition is a new line under the row, dated.
